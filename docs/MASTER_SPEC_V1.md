# سند جامع نهایی طراحی و توسعه نرم‌افزار پایش مراکز و ارتباطات شبکه
## نسخه مرجع 1.0
### 1. هدف پروژه
طراحی و توسعه یک نرم‌افزار اندرویدی APK برای پایش دائمی IPها و سرویس‌های شبکه که علاوه بر مانیتورینگ فنی، امکانات کامل پرونده‌سازی، ثبت قطعی، پیگیری، مدیریت تجهیزات، گزارش‌گیری، PDF، چاپ، اشتراک‌گذاری، پشتیبان‌گیری و بازیابی کامل اطلاعات را فراهم کند. محصول نباید صرفاً IP Scanner باشد؛ بلکه سامانه یکپارچه پایش شبکه، مدیریت مراکز، مدیریت سرویس‌ها، مدیریت قطعی‌ها، پیگیری، مستندسازی و گزارش‌گیری باشد.
### 2. ساختار اصلی اطلاعات
ساختار Canonical داده: استان/گروه → مرکز → IP → سرویس/Port → Incident قطعی → پیگیری. هر مرکز می‌تواند چند IP و هر IP چند سرویس داشته باشد. هر IP پرونده مستقل دارد و هر IP+Port نیز سرویس و تاریخچه مستقل دارد.
### 3. گروه‌بندی
گروه‌بندی باید جغرافیایی، سازمانی، مرکز، Range/CIDR و Backup Range را پشتیبانی کند. نمونه: استان تهران → مرکز وصال → چند IP → چند سرویس. همه گروه‌ها و روابط در تمام مراحل قابل ویرایش باشند.
### 4. پرونده مرکز
پرونده مرکز شامل نام، استان، گروه، نشانی، مسئول، شماره تماس، شماره تماس اضطراری، توضیحات، Range، Backup Range، تعداد IP، تعداد سرویس، سلامت مرکز، آخرین بررسی، آخرین قطعی و تعداد پیگیری باز باشد.
### 5. پرونده IP
پرونده IP شامل عنوان، IP Address، مرکز، استان، گروه، Range، Backup Range، فعال/غیرفعال بودن Monitoring، فعال/غیرفعال بودن Ping، فاصله Ping، توضیحات عمومی و فنی و تمام اطلاعات دارایی باشد.
### 6. اطلاعات دارایی
فیلدهای پایه: شماره تماس اضطراری، شماره اموال، IMEI، شماره سریال سیم‌کارت، شماره سریال دستگاه، شماره اختصاصی، نام اپراتور، نوع تجهیز، سازنده، مدل و توضیحات.
### 7. فیلدهای سفارشی
کاربر از تنظیمات بتواند هر تعداد فیلد سفارشی با عنوان، نوع داده، ترتیب، اجباری/اختیاری، فعال/غیرفعال و توضیح تعریف کند. انواع داده: متن، عدد، تاریخ، تاریخ‌وساعت، تلفن، بله/خیر، لیست انتخابی و متن چندخطی. فیلدی که در هیچ رکوردی استفاده نشده حذف واقعی شود؛ فیلدی که حتی یک بار استفاده شده حذف نشود و فقط غیرفعال/آرشیو گردد.
### 8. Ping و Port Check
Ping/ICMP مستقل از Port Check باشد و Ping پورت ندارد. Port Check برای TCP/UDP سرویس‌ها انجام شود. ممکن است Ping وصل و یک Port قطع باشد؛ بنابراین وضعیت هرکدام مستقل ذخیره شود.
### 9. فعال/غیرفعال‌سازی Ping
Ping هر IP به‌صورت تکی قابل روشن/خاموش‌کردن باشد. با انتخاب چند IP، مرکز، گروه، استان، Range یا نتایج فیلتر جاری بتوان Ping را گروهی فعال/غیرفعال کرد. قبل از تغییر گسترده تعداد موارد تحت تأثیر نمایش و تأیید گرفته شود. خاموش کردن Ping نباید Port Monitoring را متوقف کند و برعکس.
### 10. فاصله پایش و تنظیمات سلسله‌مراتبی
فاصله پایش به‌صورت دستی قابل تعیین باشد؛ نمونه 10، 20، 30، 60 ثانیه، 2 دقیقه یا مقدار دلخواه. اولویت تنظیمات: عمومی → گروه → مرکز → IP → سرویس. سطح پایین‌تر Override کند. Timeout، Retry و فاصله Retry نیز قابل تنظیم باشند.
### 11. ورود IP
سه روش اصلی: ورود دستی IP خاص، بازه From IP تا To IP، و CIDR مانند /24، /16 و سایر Prefixهای استاندارد. سیستم IPهای Range را محاسبه کند.
### 12. ورود گروهی
هنگام ورود Range کاربر بتواند نام گروه، استان، مرکز، Range، Backup Range، روش بررسی، فاصله، Port مشترک، Preset و توضیحات را تعیین کند. حالت پیشنهادی پیش‌فرض Ping فعال باشد. کاربر بتواند فقط Ping، Ping+Port یا فقط Port انتخاب کند و یک Port خاص را برای کل Range اعمال کند.
### 13. پیش‌نمایش Range
قبل از ثبت نهایی تعداد IP، روش بررسی، Port، فاصله پایش، گروه و بار تقریبی نمایش داده شود و سپس تأیید نهایی انجام شود.
### 14. Rangeهای بزرگ
برای /16 و Rangeهای بزرگ تعداد IP، تعداد Check و بار تقریبی نمایش داده شود. موتور Monitoring باید Queue، Batch، Worker Pool/Coroutine، Connection Limit و Backoff داشته باشد تا گوشی تحت فشار قرار نگیرد.
### 15. پورت‌های استاندارد پیشنهادی
فهرست اولیه شامل 22 SSH، 23 Telnet، 25 SMTP، 53 DNS، 80 HTTP، 110 POP3، 123 NTP، 143 IMAP، 161/162 SNMP، 389 LDAP، 443 HTTPS، 445 SMB، 502 Modbus TCP، 554 RTSP، 993 IMAPS، 995 POP3S، 1433 SQL Server، 1521 Oracle، 1883 MQTT، 3306 MySQL، 3389 RDP، 5432 PostgreSQL، 5900 VNC، 5060/5061 SIP، 8080 HTTP Alternative، 8291 Winbox، 8443 HTTPS Alternative، 8883 MQTT TLS و 9100 JetDirect باشد. انتخاب Port نام سرویس/پروتکل را پیشنهاد دهد ولی قابل ویرایش باشد. پورت سفارشی همیشه مجاز باشد.
### 16. Preset تجهیزات
Presetهای اولیه Router/Firewall، Modem، MikroTik، DVR/NVR، IP Camera، PLC/Industrial، VoIP/PBX، Server، Database Server و Network Printer باشند. هر Preset شامل Port، Protocol و برچسب استاندارد یا سازنده‌محور باشد. کاربر قبل از اعمال Portها را انتخاب/لغو کند. Preset نباید بدون تأیید Port موجود را حذف یا بازنویسی کند. Preset سفارشی نیز قابل ساخت/کپی/ویرایش باشد.
### 17. تشخیص قطعی
یک Failure به‌تنهایی قطعی قطعی نباشد. اولین Failure وضعیت مشکوک ایجاد کند، Retry انجام شود و اگر تا زمان تأیید قطعی پاسخ نیامد Incident ثبت شود. زمان پیش‌فرض تأیید قطعی 1 دقیقه و قابل تغییر باشد. زمان تأیید وصل مجدد نیز قابل تنظیم باشد.
### 18. وضعیت‌های فنی و رنگ‌ها
سبز=وصل، قرمز=قطع، نارنجی=مشکوک/هشدار/قطعی جدید، بنفش=پیگیری، زرد=در حال پیگیری، خاکستری=Monitoring غیرفعال یا هنوز بررسی نشده، آبی=عملیات و کنترل‌های اصلی UI.
### 19. وصل مجدد و Incident
با بازگشت ارتباط زمان وصل ثبت، مدت قطعی محاسبه، Incident بسته و وضعیت سبز شود. هر Incident شامل شماره، IP، Port، سرویس، مرکز، استان، شروع، پایان، مدت، تعداد Failure، علت احتمالی، نتیجه، پیگیری‌ها و توضیحات باشد.
### 20. Flapping Control
اگر سرویس در مدت کوتاه چند بار وصل/قطع شود برنامه ده‌ها اعلان ایجاد نکند؛ یک وضعیت ناپایداری/Flapping ثبت کند و تعداد و الگوی آن در تاریخچه نگهداری شود.
### 21. Maintenance Mode
برای گروه، مرکز، IP یا سرویس Maintenance Mode با بازه زمانی قابل تعریف باشد. Monitoring می‌تواند ادامه یابد ولی هشدار عادی ارسال نشود و قطعی Maintenance در آمار خرابی عادی محاسبه نشود.
### 22. اهمیت سرویس
هر سرویس درجه اهمیت عادی، مهم یا حیاتی داشته باشد. قطع سرویس حیاتی بتواند سلامت مرکز را قرمز کند.
### 23. سلامت مرکز
سلامت مرکز از زیرمجموعه‌ها محاسبه شود و خلاصه‌ای مانند 4 سرویس، 3 وصل، 1 قطع، آخرین قطعی و تعداد پیگیری باز نمایش داده شود.
### 24. صفحه اصلی
صفحه اصلی ساده، خلوت و هوشمند باشد. در نگاه اول کارت‌های کل مراکز، وصل، قطع، قطعی جدید، پیگیری باز و پیگیری سررسیدشده دیده شوند. سپس جست‌وجوی هوشمند و موارد مهم/قطع نمایش داده شوند.
### 25. ناوبری اصلی
پنج تب اصلی: خانه، قطعی‌ها، پیگیری‌ها، گزارش‌ها، تنظیمات. Bottom Navigation مطابق سبک تصویری تأییدشده باشد و دکمه شناور + برای افزودن سریع مرکز، IP، Range و سرویس/Port وجود داشته باشد.
### 26. Drill-down
تمام کارت‌ها و ردیف‌های صفحه اصلی و لیست‌ها فعال باشند. ضربه کوتاه یک لایه پایین‌تر را باز کند: استان/گروه → مرکز → IP → سرویس/Port → پرونده و تاریخچه.
### 27. Selection Mode
مکث طولانی روی آیتم حالت انتخاب چندتایی را فعال کند. کاربر بتواند یک، چند یا «انتخاب همه» انجام دهد. انتخاب همه فقط نتایج/فیلتر جاری را انتخاب کند، نه لزوماً کل دیتابیس.
### 28. عملیات گروهی
در Selection Mode امکان PDF، Print، Share، فعال/غیرفعال‌سازی Ping، فعال/غیرفعال‌سازی Port Monitoring، انتقال گروه، تغییر فاصله بررسی و ویرایش گروهی فیلدهای مشترک وجود داشته باشد. پس از انتخاب، چرخ‌دنده برای ویرایش فعال شود؛ یک مورد=ویرایش کامل، چند مورد=ویرایش امن فیلدهای مشترک.
### 29. جست‌وجوی هوشمند
جست‌وجوی سراسری در نام مرکز، استان، گروه، IP، Range، Backup Range، Port، سرویس، IMEI، شماره اموال، سریال دستگاه، سریال سیم‌کارت، شماره اختصاصی، شماره تماس، توضیحات و فیلدهای سفارشی انجام شود.
### 30. مرتب‌سازی
مرتب‌سازی بر اساس گروه، استان، نام/حروف الفبا، IP، وضعیت، مدت قطعی، تعداد قطعی، آخرین اتصال و آخرین قطعی با حالت صعودی و نزولی وجود داشته باشد.
### 31. تب قطعی‌ها
دو حالت قطعی فعلی و تاریخچه قطعی. فیلترها شامل کل کشور، استان، گروه، مرکز، Range/CIDR، Backup Range، IP، Port، سرویس، بازه زمانی، اهمیت، Maintenance و وضعیت پیگیری باشند. کاربر بتواند IPهای قطع یک استان، Portهای قطع یک IP، قطعی‌های کل کشور یا قطعی‌های یک Range را فوراً ببیند.
### 32. تب پیگیری‌ها
همه موارد پیگیری‌دار با وضعیت جدید، باز، در حال پیگیری، منتظر پاسخ، ارجاع‌شده، سررسیدشده، انجام‌شده و بسته‌شده نمایش داده شوند. هر IP، سرویس، Incident یا مرکز تعداد نامحدود پیگیری داشته باشد.
### 33. اطلاعات پیگیری
هر پیگیری شامل موضوع، تاریخ و ساعت، مسئول، شرح، نتیجه، وضعیت، موعد بعدی، یادآور، فایل، یادداشت و ارتباط با Incident باشد. از لیست پیگیری با یک لمس پرونده مرتبط باز شود.
### 34. یادداشت و فایل
مرکز، IP، سرویس، Incident و پیگیری امکان افزودن یادداشت، تصویر، فایل و مستندات داشته باشند و این ضمائم نیز جزو Backup کامل باشند.
### 35. تاریخ و ساعت هجری شمسی
در تمام UI هرجا ساعت نمایش داده می‌شود تاریخ هجری شمسی نیز کنار آن باشد. نمونه: ۱۴۰۵/۰۶/۰۹ - ۱۵:۴۲. فرمت رسمی: دوشنبه ۱۴۰۵/۰۶/۰۹ - ساعت ۱۵:۴۲:۱۸. زمان در دیتابیس به Timestamp استاندارد ذخیره و در UI/گزارش به Jalali نمایش داده شود.
### 36. اعلان‌ها
در قطعی تأییدشده اعلان شامل مرکز، IP، سرویس، Port و تاریخ/ساعت شمسی شروع نمایش داده شود. در وصل مجدد نیز مدت قطعی و تاریخ/ساعت شمسی وصل اعلام شود.
### 37. گزارش‌گیری
گزارش برای کل کشور، استان، گروه، مرکز، IP، Port، Range، Backup Range، CIDR، لیست انتخابی و نتایج فیلتر جاری قابل تولید باشد. گزارش‌های آماری شامل قطعی فعلی، بیشترین تعداد/مدت قطعی، امروز/هفته/ماه، پیگیری باز/عقب‌افتاده و قطعی بدون پیگیری باشد.
### 38. PDF، چاپ و اشتراک‌گذاری
PDF پرونده یک مرکز، IP، سرویس، گروه، استان، Range، چند IP انتخاب‌شده، قطعی‌ها، پیگیری‌ها و کل کشور تولید شود. همان خروجی قابل Print و Share از Android Share Sheet باشد.
### 39. تاریخ و ساعت گزارش
در تمام PDF/Print/Share خروجی، تاریخ و ساعت تهیه گزارش به هجری شمسی به‌وضوح درج شود. مثال: تاریخ تهیه گزارش ۱۴۰۵/۰۶/۰۹، ساعت ۱۵:۴۲:۱۸. گزارش IP یا Range باید Range/IP و زمان تهیه را در Header/Metadata داشته باشد.
### 40. تایپوگرافی UI
فونت اصلی رابط نرم‌افزار Vazirmatn باشد.
### 41. تایپوگرافی گزارش
فونت رسمی و ثابت Report/PDF/Print برابر Vazirmatn UI FD باشد و از Font Picker رابط تأثیر نگیرد. وزن‌ها: عنوان اصلی Bold 700 اندازه 18–20، عنوان بخش SemiBold 600 اندازه 14–16، زیرعنوان Medium 500 اندازه 12–14، متن Regular 400 اندازه 11–12، عنوان جدول SemiBold 600 اندازه 10–11، جدول Regular 400 اندازه 9–10، اعداد/تاریخ Regular/Medium اندازه 9–11، نتیجه مهم Bold 700 اندازه 11–12، پاورقی Regular اندازه 8–9.
### 42. PDF و RTL
فونت در PDF Embed شود. RTL، اتصال حروف فارسی، اعداد فارسی، تاریخ شمسی، شکست خطوط، عدم بریده‌شدن جداول، وزن‌های Regular/Medium/SemiBold/Bold و یکسانی Preview/PDF/Print تست شوند. هیچ Font Controller یا Settings Store موازی ساخته نشود.
### 43. Style Guide رابط
فرمت تصویری مرجع پروژه: پس‌زمینه سفید/روشن، Accent آبی، کارت‌های Rounded و تمیز، RTL، فاصله‌گذاری مناسب، Minimal/Modern/Smart. سبز برای وصل، قرمز قطع، نارنجی هشدار، بنفش پیگیری، زرد در حال پیگیری، خاکستری غیرفعال. طرح تصویری تأییدشده مرجع UI/UX است و هویت نهایی برنامه باید همین زبان بصری را حفظ کند.
### 44. Backup کامل
اصل قطعی: هیچ داده کاربر یا داده تولیدشده سیستم خارج از Backup نماند. Backup شامل گروه‌ها، استان‌ها، مراکز، IPها، Portها، سرویس‌ها، Rangeها، Backup Rangeها، تنظیمات Monitoring/Ping/Timeout/Retry، تاریخچه اتصال، Incidentها، پیگیری‌ها، یادداشت‌ها، فایل‌ها، فیلدهای سفارشی و مقادیرشان، اطلاعات دارایی، Presetها، تنظیمات گزارش، تنظیمات برنامه و داده امنیتی قابل انتقال به‌صورت امن باشد.
### 45. نام و Metadata فایل Backup
نام Backup تاریخ و ساعت هجری شمسی داشته باشد؛ نمونه: `Backup_1405-06-09_15-42-18.backup`. داخل فایل نیز تاریخ/ساعت شمسی Backup، نسخه برنامه، نسخه دیتابیس، تعداد مراکز/IP/سرویس و شناسه Backup ثبت شود.
### 46. Restore کامل
Restore باید کل اطلاعات را برگرداند. قبل از هر Restore یک Backup اضطراری خودکار از وضعیت فعلی تهیه شود. سازگاری نسخه دیتابیس بررسی و Migration ایمن انجام شود. در صورت خطا، داده فعلی از بین نرود.
### 47. امنیت Backup
امکان رمزگذاری Backup پیش‌بینی شود. داده حساس Plain Text ذخیره نشود. فایل Backup قابل انتقال به همان یا دستگاه دیگر باشد.
### 48. امنیت برنامه
بخش امنیت شامل Username، Password، تغییر آن‌ها، سؤال امنیتی و پاسخ برای Forgot Password، Auto Lock، و در صورت امکان PIN سریع و Biometric باشد. رمز و پاسخ سؤال امنیتی Plain Text ذخیره نشوند.
### 49. Auto Lock
گزینه‌های خاموش، 1 دقیقه، 5 دقیقه، 15 دقیقه و پس از خروج از برنامه در نظر گرفته شود.
### 50. تنظیمات
Settings حداقل شامل Monitoring، Ping/Port، Timeout/Retry، تشخیص قطعی/وصل، Flapping، Maintenance، Port Presets، Device Presets، Custom Fields، Range/Backup Range، Reports/PDF/Print، Backup/Restore/Encryption، Username/Password/Recovery و Auto Lock/Biometric باشد.
### 51. حذف و Referential Integrity
حذف مرکز، IP، Range، تاریخچه، Backup و داده‌های مهم با تأیید انجام شود. هیچ داده دارای وابستگی بدون کنترل Referential Integrity حذف نشود. فیلد سفارشی استفاده‌شده فقط آرشیو شود.
### 52. ویجت اندروید
به‌عنوان قابلیت آینده، Widget نمایش کل مراکز، وصل، قطع، پیگیری باز و آخرین به‌روزرسانی در نظر گرفته شود و با لمس برنامه باز شود.
### 53. معماری Server-ready
نسخه 1.0 Local-first باشد اما Domain/Data Layer طوری طراحی شود که بعداً Backend مرکزی، چند گوشی، چند کاربر، Sync و Web Dashboard بدون بازنویسی کامل اضافه شوند.
### 54. فناوری پیشنهادی
Android با Kotlin + Jetpack Compose، دیتابیس Room، معماری لایه‌ای Domain/Data/UI، Coroutines/Flow، Foreground Service برای پایش فعال، Queue/Worker Pool برای Probeها و WorkManager فقط برای کارهای غیرلحظه‌ای مناسب. سیستم PDF باید فارسی، RTL و Font Embed را مطمئن پشتیبانی کند.
### 55. Performance و پایداری
Monitoring رابط UI را Block نکند. Concurrency کنترل‌شده، Timeout، Retry، Backoff، Queue و Batch استفاده شوند. از ایجاد اعلان‌های تکراری جلوگیری شود. برنامه پس از Resume/Restart وضعیت Monitoring و Incidentهای باز را سازگار بازیابی کند.
### 56. معیار پذیرش نسخه 1.0
ورود دستی IP، Range/CIDR، Ping مستقل، Port Monitoring، عملیات گروهی Ping، تشخیص قطعی و وصل، Incident، Flapping، Maintenance، اهمیت سرویس، تاریخچه، پیگیری متعدد، فیلد سفارشی، Port/Device Preset، جست‌وجو و مرتب‌سازی، فیلتر قطعی‌ها، Selection Mode، PDF/Print/Share، تاریخ/ساعت شمسی، استاندارد گزارش Vazirmatn UI FD، Backup/Restore کامل، Backup اضطراری پیش از Restore، Login/Recovery و UI مطابق Style Guide باید همگی کار کنند.
### 57. اصول نهایی پروژه
اصل اول: سادگی در ظاهر و قدرت در عملکرد. اصل دوم: هر IP/سرویس پرونده و تاریخچه مستقل داشته باشد. اصل سوم: Monitoring و پیگیری مدیریتی به هم متصل باشند. اصل چهارم: همه داده‌ها قابل گزارش، Backup و Restore باشند. اصل پنجم: جزئیات پیچیده فقط با Drill-down نمایش داده شوند. اصل ششم: هیچ معماری موازی برای تنظیمات، فونت، Backup، Monitoring یا Reports ایجاد نشود.
